This box calls smart.chrif.net with model: "auto". If a provider fails, the router retries the next best free model automatically.

Why an auto router?

Free AI APIs go down, rate-limit you, or retire models without warning. Instead of hardcoding one provider, the app asks for the best available model and the router handles the failover.

  • 1Request arrives with model: "auto".
  • 2Healthy providers are tried in priority order.
  • 3On timeout or error, the next model is tried instantly.
  • 4The first good answer is returned, with the provider name attached.

Developer API

OpenAI-compatible. Zero setup.

Point any OpenAI client at the router, set the model to auto, and you're done. No key required for keyless providers.

Endpoint

Standard chat-completions schema. Streaming, system prompts, temperature and JSON mode are supported.

POSThttps://smart.chrif.net/v1/chat/completions
GEThttps://smart.chrif.net/v1/models
GEThttps://smart.chrif.net/health

Every response includes an x_router object with the chosen provider, attempt count and latency, plus the headers X-Router-Provider and X-Router-Attempts.
